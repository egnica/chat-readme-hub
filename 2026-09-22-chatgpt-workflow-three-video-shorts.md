# Three Short Videos: ChatGPT Workflow Series

**Date:** September 22, 2026

## Series Goal

Create three very concise short-form videos around a practical ChatGPT workflow. Each video should stand on its own, but together they show a progression:

1. ChatGPT Projects can hold instructions that persist across chats.
2. ChatGPT can connect to third-party applications.
3. Those two ideas can be combined into a custom tool and workflow.

The videos should move fast and rely heavily on screen recording and visual demonstration instead of long explanations.

---

## Video 1: Project Instructions

### Opening

- Start on camera with the **“Welcome Back”** music cue.
- On-screen text: **Did you know?**
- Go directly into the point without saying “did you know” out loud.

### Core Line

> Inside a ChatGPT project, you can set instructions that apply across every chat inside that project.

### Demo Flow

1. Create a new ChatGPT Project on screen.
2. Open **Project Instructions**.
3. Add a clear instruction or workflow rule.
4. Start a chat inside the project.
5. Show the instruction working in a real conversation.
6. Use a trigger such as **“wrap this up”** and show the resulting note/export.

The goal is to show the feature, not over-explain it.

### End / Tease

Briefly point toward the next idea: connecting ChatGPT to outside applications so the result can be saved somewhere useful.

---

## Video 2: Connect Third-Party Applications

### Opening

- Same **“Welcome Back”** music cue.
- On-screen text: **Did you know?**

### Core Line

> You can connect third-party applications directly to ChatGPT.

### Demo Flow

1. Show the connections / apps area in ChatGPT.
2. Show one recognizable example such as Notion or GitHub.
3. Demonstrate the practical result rather than spending time on setup.

### Payoff Line

> So instead of copying everything back and forth, ChatGPT can work with the application.

### End / Tease

Lead into the idea that once ChatGPT can both follow persistent instructions and save information outside the chat, those concepts can become the foundation of a custom application.

---

## Video 3: Chat to Tool

### Opening

This one should not use **Did you know?** because it is a showcase rather than a feature tip.

- Same visual style / music cue if it still feels consistent.
- On-screen text: **Chat to Tool**

### Core Concept

> If chat remembers my instructions and can save my files, I can turn that into a tool.

Then immediately show the application.

### Main Line

> I built one that takes a conversation and, with one click, turns it into a blog post on my site.

### Demo Flow

Keep the demo phone-first and easy to understand:

1. Have the conversation in ChatGPT.
2. Save the resulting note/content into GitHub, which acts as the content manager behind the application.
3. Open the Chat Notes / Markdown library application.
4. If the post needs images, use the connected image uploader.
5. The uploader sends images to S3 and converts them into web-friendly files.
6. Use the blog action/button to move the content into the blog workflow.
7. Show the finished post rendering directly on the website.

The important point is not the technical architecture. The important point is that the entire workflow can happen from the phone: conversation → saved content → images → blog → live website.

### Positioning

This is the payoff of the series. It shows what can be built when persistent instructions and external saving/connectivity are combined into a purpose-built workflow.

The video should still work for someone who never saw the first two shorts. The previous videos can be linked in the description rather than required context in the spoken script.

### Contact Hook

Possible ending:

> If you're curious how a flow like this could fit your work, get in touch.

Or, even tighter:

> If that's useful to you, let's talk.

## Style Notes

- Keep every video lean.
- Show more than you explain.
- Let on-screen text do some of the work so the spoken script can stay shorter.
- Avoid language such as “small” or “quick” when describing the tool itself because it can make the value feel smaller.
- Keep the language accessible. Use **ChatGPT** rather than **LLM** unless the technical distinction actually matters.
- The third video should feel like the strongest payoff: a real application built around the concepts introduced in the first two videos.
